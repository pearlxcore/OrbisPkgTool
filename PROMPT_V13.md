## Empirical discoveries while building the harness (Sony behaviors)

1. `img_create gp4_path out_path` — **out_path is a FILE path** (extensionless,
   must NOT pre-exist; a pre-existing directory with that name = "Could not
   create output file").
2. `orig_path` in the GP4 resolves **relative to the GP4's own directory**
   (write the GP4 inside the source folder).
3. Sony img_create **REJECTS user-provided system files** it regenerates:
   `sce_sys/license.dat`, `license.info`, `psreserved.dat`,
   `playgo-chunk.dat/.sha`, `playgo-manifest.xml` → "The file name is not
   valid." Only `sce_sys/param.sfo` is required + user-provided. (This goes
   beyond the playgo-only cleanup in the older tutorials.)
4. Sony injects `sce_discmap.plt` + `sce_sys/about/right.sprx` on build.
5. Sony img_verify warning profile: ours == original (R4211/R4124 parity).

## OpenOrbis validator finding (informative, not a defect)

OpenOrbis's `PkgValidator` **rejects the Content Digest and Major Param
Digest** on any package whose param.sfo metadata was REGENERATED by the
builder (Sony rewrites PUBTOOLINFO/PUBTOOLVER; our builder rewrites
PUBTOOLINFO). So OpenOrbis-validate FAILs on Sony-built and our-built
packages whose SFO differs from its recomputation, while the HASH-level
checks pass. Classified `EXPECTED_DIFFERENCE` in the harness.

## How to run (your Digimon validation)

```powershell
# 1. CrossValidation\config.example.json → config.json, set paths
#    (reference_pkg = original Digimon, ours_pkg = digi_FINAL.pkg)
# 2. dotnet build .\CrossValidation\OpenOrbisDriver -c Debug
# 3. .\CrossValidation\Run-QuickValidation.ps1   (fast)
#    .\CrossValidation\Run-FullValidation.ps1    (everything; ~4x pkg size disk)
```

Every run → `Results/<timestamp>_<label>/` with `00_environment.txt`,
`capabilities.txt`, `summary.txt`, per-tool dirs, Comparisons/, GP4/,
InnerPfs/, OuterPfs/, RoundTrips/ and a full text log per external command
(command, cwd, timestamps, duration, exit code, stdout+stderr).

## Notes

- PS 5.1 compatibility was required (no pwsh on the machine): native-stderr
  capture via temp file (EAP=Stop breaks 5.1 native stderr), manual
  GetRelativePath, dual-layout SFO parser (our 16-byte index entries vs
  Sony's 32-byte embedded-name entries).
- The harness does NOT modify the frozen core; if a real mismatch appears,
  preserve logs and report before changing production code.
- The Digimon 11.9 GB full run is intentionally left for the user.
